# RULES — накопленные правила проекта

Правила добавляются агентом по указанию TASK.md. Каждое правило имеет ID `R-NNN`, дату, итерацию и формулировку. Устаревшие правила не удаляются, а помечаются `[deprecated: iter-NNN]`.

## Формат записи
```
R-001 (iter-001, YYYY-MM-DD): <правило одной фразой>
R-002 (iter-003, YYYY-MM-DD): <правило>
```

## Правила

```
R-001 (введено iter-001, 2026-10-26; формализовано iter-002, 2026-10-26): язык всех артефактов и ответов — русский, кроме кода, схем и идентификаторов, где язык диктуется техническими ограничениями (по умолчанию английский).
R-002 (введено iter-001, 2026-10-26; формализовано iter-002, 2026-10-26): Оркестратор не пишет код и не правит файлы в репозитории напрямую — он читает репозиторий, планирует итерацию, формулирует TASK.md и принимает REPORT.md; финальное решение всегда за человеком.
R-003 (введено iter-001, 2026-10-26; формализовано iter-002, 2026-10-26): любые изменения в проекте выполняются только по заданию в TASK.md и фиксируются в REPORT.md; отклонение от TASK.md допускается исключительно через раздел «Отклонения» в REPORT.md с обоснованием.
```

Формулировки перенесены без изменений смысла из документов рабочего процесса (по требованию TASK.md iter-002 — не изобретать новые):

## Примечания по ведению

- Правила `R-001`…`R-003` применялись с `iter-001` по тексту TASK.md, поскольку настоящий раздел был пуст; это расхождение зафиксировано в `DL-001` (пункт «Сопутствующие решения») и устранено в `iter-002` записью `DL-002`.
- Дата в скобках — дата введения правила в оборот проекта; для правил, введённых до создания настоящего раздела, указывается итерация введения и итерация формализации.
- Новое правило добавляется только по явному указанию в TASK.md; номер — следующий за последним видимым.
